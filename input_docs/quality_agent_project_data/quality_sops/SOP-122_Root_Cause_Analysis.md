# SOP-122: Root Cause Analysis Procedure

**ISO 9001:2015 Reference:** Clause 10.2, Clause 9.1.3 (Analysis and Evaluation)

## Purpose
Establishes a structured methodology for determining the true underlying cause of a quality issue, rather than addressing symptoms.

## Scope
Applies to all CAPAs and any investigation classified as Medium or High severity.

## Procedure
1. **Problem Statement**: Define the issue in measurable, specific terms (what, where, when, how much) before analysis begins. Vague problem statements must be rejected and returned for clarification.
2. **Methodology Selection**: Select an appropriate root cause tool based on complexity:
   - **5-Why Analysis** for straightforward, single-cause issues.
   - **Fishbone (Ishikawa) Diagram** for issues with multiple potential contributing factors (Man, Machine, Method, Material, Measurement, Environment).
   - **Fault Tree Analysis** for complex, safety-critical, or systemic failures.
3. **Data Collection**: Root cause conclusions must be supported by objective evidence — process data, equipment logs, operator interviews, or test records — not assumption alone.
4. **Verification of Root Cause**: The proposed root cause must be validated, where feasible, by demonstrating that removing or correcting the cause eliminates the defect (e.g., a controlled trial run).
5. **Documentation**: The completed root cause analysis, including methodology used and supporting evidence, must be attached to the CAPA record before the corrective action plan is drafted.

## Common Pitfalls to Avoid
- Stopping at the first plausible cause without verification.
- Confusing a contributing factor with the true root cause.
- Proposing corrective actions before root cause is confirmed.
